# 观测出口方案（Obs Server）

> 范围：内网验证。115 只做 NFS。
>
> **本轮：单机多卡，每用户一只容器。训练里的 `ObsInstrServer` 照旧当收件箱；容器里加一个常驻转发进程，把画面送到宿主机。算法包尽量不改。多机多卡以后再说。**

---

## 1. 这轮做什么

- 训练仍用现成链路：各卡 `StepObsPublisher` → rank0 `ObsInstrServer`（占容器内 `15555`，不映射出去）。
- 容器再放一个**常驻转发进程**，和 Server B 一起随 docker 起。它不抢 `15555`。
- 训练一跑，`ObsInstrServer` 用已有的 HTTP 中继，把位置 / 姿态 / 关节 POST 到本机转发进程；转发进程再从 `15557` 发给外面的 client。
- **谁的画面，看连的是哪个地址。** 报文不写用户名、不写任务号。
- 同一人接着跑第二份训练，还是这一个画面口。要不要重连，客户端自己处理。
- 任务结束不删容器；只有 `POST /containers/stop` 才删。训完后没有新帧，已连着的画面停在最后一帧。
- 这轮不做远程改切片，A 不映射 `15556`。

---

## 2. 为什么用转发，而不是拆走收件箱

`ObsInstrServer` 已经会收各卡数据，并带 `RSL_RL_ISRC_OBS_RELAY_URL` 中继。打开这个环境变量、本机加一个转发进程，**不用改它的代码，也不用改 `StepObsPublisher` 的接线**。

常驻进程不能去听 `15555`：那个口训练 rank0 已经占了。它只能接 `ObsInstrServer` 主动 POST 出来的副本。

---

## 3. 容器里怎么跑

```
docker run runner-alice          ← containers/start
  ENTRYPOINT
    ├─ Server B     :8080
    └─ 转发进程
         HTTP  127.0.0.1:15558   ← 只收本机 ObsInstrServer 的 POST（不映射）
         PUB   *:15557           ← 画面口，映射到宿主机

之后 POST /tasks/start → torchrun（不要加 --no-zmq-obs）
  各卡 StepObsPublisher → rank0 ObsInstrServer :15555
  ObsInstrServer 中继 POST → 127.0.0.1:15558
  转发进程 PUB → 15557 → 宿主机 client
```

要点：

- `15555` 仍在训练里，不映射到宿主机。
- 画面口必须绑 `0.0.0.0`。HTTP 只绑本机。
- 入口脚本：先起转发（挂了自动拉起），再起 Server B。转发挂了不要杀整个容器。
- 官方脚本保持默认（会起 `ObsInstrServer`）。用户加 `--no-zmq-obs` 或自己写脚本不起收件箱，平台 **不拦**，转发没有数据、没画面即可。

中继超时要设得很短（例如 `RSL_RL_ISRC_OBS_RELAY_TIMEOUT=0.05`）。现有实现是同步 POST，转发若卡住会拖训练里的收件循环。

---

## 4. 画面里有什么

HTTP 中继已经是每个环境一行：`[位置, 姿态, 关节]`。切片仍用 `ObsInstrServer` 默认：**最多 64 个**（`min(64, 环境数)`）。

转发进程里留一个 **转换函数**：收到 POST 后先经过它，再 PUB。这轮默认原样拷贝（和 POST 内容一样），不写用户名。以后 client 要别的样子，只改这个函数，不要做格式开关名单。

某一帧 POST 失败（转发慢了、还没起来）：丢掉这一帧，训练继续，不要重试。画面跟不跟得上，客户端自己的事。

---

## 5. Server A 这轮改什么

现有 `31000–31999 → 8080` 之外，再一段：

| 池 | 映射 | 返回字段 |
|----|------|----------|
| `32000–32999` | → 容器 `15557` | `obs_pub_endpoint` |

`containers/start`、`containers/current`、`login` 都返回 `obs_pub_endpoint`。不映射 `15555` / `15556`。

`docker run` 增加：

```
-p {internal_ip}:{obs_pub_host}:15557
-e OBS_ENABLE=1
-e OBS_PUB_PORT=15557
-e OBS_RELAY_HTTP=http://127.0.0.1:15558/post
-e RSL_RL_ISRC_OBS_RELAY_URL=http://127.0.0.1:15558/post
-e RSL_RL_ISRC_OBS_RELAY_TIMEOUT=0.05
```

就绪：B 的 `/health` 通，并且宿主机画面口能 TCP 连通。失败则删容器，31xxx 和 32xxx 一起释放。

幂等 start：容器还在就返回正在跑的那只，**不准偷偷删掉重建**。老容器没有画面口时，画面地址可以没有；要换新口，用户自己 `containers/stop` 再 `start`。A 重启后两段端口都要记为占用。

先发带转发进程的镜像，再发 A。旧镜像没有 `15557` 会健康检查失败。

---

## 6. 客户端怎么用

```
1. 登录 → 挂 NFS
2. 建容器 → 拿到任务地址 + 画面地址（此时可连，暂无画面）
3. 可视化连画面地址
4. 对任务地址 start（不要 --no-zmq-obs）
5. 有画面（最多 64 个机器人）
6. 任务结束：容器还在，画面停在最后一帧；可再 start
7. 停容器：删容器，地址作废
```

alice / bob 画面地址不同。连错才会串。

## 7. 这轮明确不做

| 不做 | 原因 |
|------|------|
| 拆掉训练里的 `ObsInstrServer` | 本轮用中继转发，改动更小 |
| 改 `StepObsPublisher` 去连常驻进程 | 不需要 |
| 把 `15555` 映射出去 | 那是收口，不是画面口 |
| 映射控制口 `15556` | 这轮只要画面 |
| 报文里写用户名 / 任务号 | 地址已经区分用户 |
| 为停训发心跳 | 画面停在最后一帧即可 |
| 拦 `--no-zmq-obs` / 替用户重建容器 | 没画面或没有画面口时，用户自己决定要不要停了重开 |
| 这轮就做多种发出格式开关 | 只留转换函数，默认原样 |
| 多机多卡 | 以后再说 |

---

## 8. 改哪些地方

| 哪里 | 改什么 |
|------|--------|
| `obsserver/` | 常驻转发：本机收 HTTP → 转换函数（默认原样）→ PUB；挂了自动拉起 |
| `serverB` 入口和镜像 | 和 B 一起起转发 |
| `rsl_rl_isrc` | **不改**。靠容器环境变量打开已有中继 |
| Server A | 映射 `15557`；注入中继 URL / 短超时；start / current / login 都返回 `obs_pub_endpoint`；不替用户重建 |
| 联调 | 开训后能看见最多 64 个机器人；alice / bob 地址不同不串 |

Server B 任务 API 不转发画面，仍只起停训练。

---

## 9. 出问题先看哪

| 现象 | 先看 |
|------|------|
| 建容器成功但连不上画面 | A 有没有映射 `15557`；入口有没有起转发 |
| 有口一直没画面 | 训练开了没有；有没有 `--no-zmq-obs`；中继 URL 对不对 |
| 训练变卡 | 中继超时是否太长、转发是否把 HTTP 卡住 |
| alice 看到 bob | 客户端连错画面地址 |

---

## 10. 以后（本轮不实现）

多机多卡、拆走收件箱、远程改切片，另开文档。本轮就是：训练收件箱不动 + 本机 HTTP 中继 + 常驻 PUB。

---

## 11. 落地顺序

1. 本文约定——当前。
2. 转发进程 + 入口脚本；本机 POST 一条能从 `15557` 看到。
3. 容器内开中继环境变量，跑官方训练脚本（无 `--no-zmq-obs`）冒烟。
4. Server A 映射画面口并返回地址；alice 联调。
5. alice / bob 各连各的地址，确认不串。
